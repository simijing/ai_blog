## 重新开始写东西

上一次认真写博客，还是几年前。那时我在一个免费的博客平台上写了十几篇，后来平台改版，链接全部失效，我也就没有再登录。这件事拖了很久，直到今天我才意识到，**问题不在平台，而在我始终没有把内容当成自己的东西**。

现在这个站是我自己搭的：一堆静态文件，加上一些 Markdown。它不复杂，甚至有点简陋，但每一行我都能解释清楚。这大概就是重新开始的理由。

## 为什么又开一个博客

写作对我一直是一件“想清楚了才动笔”的事，而现实中很少有“想清楚”的时刻。于是我想换个方式：先写，再想。具体有几个原因：

- 把学到的东西讲一遍，才知道自己哪里没懂；
- 有些坑是自己踩过的，写下来能省别人的时间；
- 需要一个不依赖算法推荐的地方，安放长一点的想法；
- 练习把话说清楚，这本身是一项技能。

> 写作不是思考的记录，而是思考本身。——这句话我在很多地方见过，但直到自己开始写，才慢慢理解它。

## 这个站会写什么

内容大致分成几类，不排除以后调整：

1. **前端**：CSS、JavaScript、浏览器里那些容易被忽略的细节；
2. **AI**：我如何把模型放进日常工作流，以及它在哪里让我失望；
3. **部署**：把东西发布出去的过程，包括踩坑记录；
4. **随笔与阅读笔记**：技术之外，但和做事有关的部分。

我不会追热点，也不打算做教程站。这里的文章更像工作笔记：有上下文，有具体版本，也可能有过时的结论。如果某篇文章让你少走一段弯路，它的目的就达到了。

## 它是怎么搭起来的

技术选型只有一条原则：十年后还跑得起来。于是选了最朴素的一组：手写的 HTML、一份 CSS、几个不依赖框架的 JS 文件，内容用 Markdown 保存。本地预览只要一条命令：

```bash
python -m http.server 8000
```

然后打开 `http://localhost:8000` 就能看到效果。没有构建步骤，没有依赖需要升级，改完文件刷新页面即可。这样做当然有代价——没有热更新，也没有现成的插件生态，但对我来说，**能自己修好**比**功能多**更重要。

## 一些约定

- 文章用简体中文写，标点用全角；
- 代码块标注语言，例如 `bash`、`css`，示例尽量能直接运行；
- 引用别人的观点会给出链接，写错的地方会在原文上更正，并注明修改时间；
- 不收集读者数据，不放置第三方统计脚本。

这个站没有评论区，想讨论可以给我写信。我更喜欢一对一的交流，它比公开争论更容易把问题说清楚。

## 第一篇文章之后

写完这篇，我给自己定了一个很小的目标：每周至少写一篇，哪怕只有几百字。数量不重要，重要的是保持“把想法落到文字”的动作。如果三个月后回看，发现前面的文章写得幼稚，那说明这段时间确实在进步。
